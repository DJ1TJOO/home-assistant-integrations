# Eetlijst Integration for Home Assistant

The **Eetlijst** integration allows you to seamlessly connect your Eetlijst group to Home Assistant. Track who is eating tonight, manage shared shopping lists, view group calendar events, and view individual member statuses with real-time WebSocket updates.

---

## Features

- **Real-time Push Updates**: Instant synchronization via WebSockets when members sign up, change status, or edit the shopping list.
- **Meal & Headcount Tracking**: View today's total headcount, assigned cooks, and individual member attendance.
- **Interactive To-do List**: Full create, update (check/uncheck), and delete support for the group's shopping list natively in Home Assistant.
- **Group Calendar Integration**: View upcoming scheduled meals and detailed participant breakdowns directly inside your Home Assistant calendar.
- **Manual Refresh Button**: Force a full state sync on demand.

---

## Configuration

This integration is configured entirely via the Home Assistant User Interface.

### Setup Prerequisites

Before setting up the integration, make sure you have:

#### API Token

1. Log in to your [Eetlijst Account](https://v5.eetlijst.nl/account).
2. Scroll down to the **Developer API key (BETA)** section.
3. Copy your API token.

#### Group ID

1. Open your group on [Eetlijst](https://v5.eetlijst.nl).
2. From the url copy the group id `https://v5.eetlijst.nl/groups/group/<group_id>/`

### Setup Steps

1. In Home Assistant, navigate to **Settings** $\rightarrow$ **Devices & Services**.
2. Click **Add Integration** and search for **Eetlijst**.
3. Fill in the required fields:

| Field             | Description                                                             | Default    |
| ----------------- | ----------------------------------------------------------------------- | ---------- |
| `API Token`       | Your personal API token for authentication.                             | _Required_ |
| `Group ID`        | The unique ID of the group you want to monitor.                         | _Required_ |
| `Update Interval` | Backup poll frequency in minutes (WebSockets handle real-time updates). | `60`       |
| `Previous Days`   | How many past days of events to fetch (`0` fetches all time).           | `7`        |
| `Limit`           | Maximum number of event records to fetch (`0` for unlimited).           | `50`       |

## Platforms & Entities

All entities generated by this integration are tied to a single Home Assistant Device named `Eetlijst <Group Name>`.

### 1. Sensors (`sensor`)

#### **Group Info Sensor**

- **Entity ID**: `sensor.eetlijst_<group_id>_info`
- **State**: Group Name
- **Icon**: `mdi:home-group`
- **Attributes**:
    - `id`: Group ID.
    - `description`: Group description text or noticeboard announcements.
    - `default_close_time`: Default time when sign-ups close.
    - `created_at`: Group creation timestamp.
    - `created_at_eetlijst`: Group creation timestamp on Eetlijst.
    - `statistics_start_date`: Start date for group statistics calculations.
    - `statistics_end_date`: End date for group statistics calculations.

---

#### **Today Event Sensor**

- **Entity ID**: `sensor.eetlijst_<group_id>_today_event`
- **State**: Total headcount for today's meal (integer count of attending members + guests).
- **Icon**: `mdi:pot-steam`
- **Attributes**:
    - `has_event`: Boolean indicating whether an event exists today.
    - `event_id`: Unique ID of today's event.
    - `name`: Name of the meal/event.
    - `description`: Event description/notes.
    - `open`: Boolean indicating if sign-ups are currently open.
    - `start_date`: Event start date and time.
    - `signup_deadline`: Cutoff deadline for meal sign-ups.
    - `closed_by`: User ID of who closed sign-ups.
    - `changed_signup_time`: Boolean indicating if sign-up cutoff time was updated.
    - `created_at`: Event creation timestamp.
    - `updated_at`: Last update timestamp.
    - `attending_count`: Total headcount (members + guests).
    - `member_count`: Number of attending members.
    - `guest_count`: Total count of extra guests.
    - `has_cook`: Boolean indicating if a cook has been assigned.
    - `cooks`: List of member names assigned to cook.
    - `grocery_buyers`: List of member names who bought groceries.
    - `attending_names`: List of usernames currently attending.
    - `attendees`: List of full attendee detail maps, containing:
        - `user_id`: Member user ID.
        - `username`: Member display name.
        - `event_id`: Event ID.
        - `event_name`: Event name.
        - `status`: Attendance status string (`cook`, `got_groceries`, `eat_only`, `not_attending`, `dont_know_yet`).
        - `number_guests`: Count of extra guests brought by member.
        - `comment`: User comment/note.
        - `created_at`: Attendance registration timestamp.
        - `updated_at`: Last status change timestamp.

---

#### **Member Sensors** _(Dynamically created for each group member)_

- **Entity ID**: `sensor.eetlijst_<group_id>_member_<user_id>`
- **State**: User's status for today's event (`cook`, `got_groceries`, `eat_only`, `not_attending`, `dont_know_yet`).
- **Entity Picture**: Profile image URL (if available).
- **Dynamic Icons**:
    - `mdi:silverware-fork-knife` (Eating / Cooking / Groceries)
    - `mdi:close-circle-outline` (Not Attending)
    - `mdi:help-circle-outline` (Don't Know Yet / Unset)

- **Attributes**:
    - `id`: Member user ID.
    - `name`: Member display name.
    - `origin`: User registration origin.
    - `email`: User email address.
    - `allergies`: List of user allergies/dietary restrictions.
    - `birthday`: User birthday.
    - `profile_image`: Profile image path.
    - `profile_image_url`: Full profile picture URL.
    - `order_of_buttom_bar`: UI bottom bar layout settings.
    - `wants_to_recieve_notifications`: Notification preference boolean.
    - `funnel_lead`: Onboarding funnel metadata.
    - `cook_points`: Accumulated cook points balance.
    - `cook_points_imports`: Historical cook points import breakdown.
    - `today_attendance`: Detailed attendance record for today (`user_id`, `username`, `status`, `number_guests`, `comment`, etc.).
    - `group_user`: Group-specific membership metadata, containing:
        - `active`: Membership active status boolean.
        - `order`: Display order rank in group.
        - `on_holiday`: Boolean indicating if user is currently on holiday.
        - `holiday_start`: Holiday start timestamp.
        - `holiday_end`: Holiday end timestamp.
        - `default_schedule`: User's default weekly attendance schedule:
            - `monday`: Default status for Mondays.
            - `tuesday`: Default status for Tuesdays.
            - `wednesday`: Default status for Wednesdays.
            - `thursday`: Default status for Thursdays.
            - `friday`: Default status for Fridays.
            - `saturday`: Default status for Saturdays.
            - `sunday`: Default status for Sundays.

---

### 2. To-do List (`todo`)

#### **Shopping List**

- **Entity ID**: `todo.eetlijst_<group_id>_shopping_list`
- **Supported Features**: Create Item, Mark Complete / Incomplete, Delete Item.
- **Behavior**: Maps directly to your Eetlijst group list. Checking off an item in Home Assistant updates it on Eetlijst in real time.

---

### 3. Calendar (`calendar`)

#### **Eetlijst Group Calendar**

- **Entity ID**: `calendar.eetlijst_<group_id>_calendar`
- **State**: Next upcoming event.
- **Icon**: `mdi:calendar`
- **Description Payload**: Rich text event description including total attendees, cooks assigned, and formatted user list with guest counts and notes.

---

### 4. Button (`button`)

#### **Sync Data Button**

- **Entity ID**: `button.eetlijst_<group_id>_sync_data`
- **Icon**: `mdi:sync`
- **Action**: Pressing this button triggers an immediate REST/GraphQL background refresh of all coordinator data.

---

## Re-authentication

If your API token expires or becomes invalid, Home Assistant will raise a persistent notification prompting you to re-authenticate. Simply enter your new API token in the re-auth prompt to restore the connection without breaking existing dashboard cards or entity IDs.
